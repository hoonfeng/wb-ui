fix: flex intrinsic heights + SVG presentation attribute sizing

Desktop probe (gou-ide/dev/desktop_probe) continued to reveal real-page
rendering defects in the Vue IDE app:

1. flex column intrinsic height: intrinsicContentHeight measured ElementBox
   children with fontLineGap (line height ≈25px) instead of the child's real
   height, so the chat-input-area (a flex row containing a 150px textarea)
   collapsed to 25px and the textarea overflowed. Now explicit child heights
   win, otherwise the child's own intrinsic height recurses; line gap is a
   last resort for text-only boxes. (chat-input-area 25 → 160px; viewport
   overflow 1094 → ~988.)

2. block container intrinsic height: a block with multiple stacked block
   children reported max(child) instead of the SUM, so a toolbar under a
   textarea (input-bottom-bar) overflowed the 160px wrapper. Block-level
   children now sum their heights. (The overflow:hidden conv-sidebar clips
   its expanded content — matching browsers.)

3. SVG / replaced-element presentation attributes: <svg width="18"
   height="18"> never mapped to CSS width/height, so every icon in the Vue
   app rendered as a 0px-wide sliver (18px tall). resolveStyle now applies
   the width/height attributes to the computed style when no stylesheet rule
   declared them (WebKit presentation-attribute semantics), covering both
   <svg> and <img>. (Icons now render at 12–32px as authored.)

TestBlockIntrinsicSum (150+35 stacked), TestFlexRowChildHeightPinned
(tallest-child height), TestSVGPresentationAttributeSize (svg 18×18),
