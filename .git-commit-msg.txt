fix: activity bar width, ring label height, flex gap in free space

Three flex layout fixes found with the desktop_probe geometry probes:

1. Activity bar buttons were 40px wide but the intrinsic-content width of
   the .activity-top flex column measured only the icon (18px) + padding,
   ignoring the button's explicit width:40. The 40px button then overflowed
   the 20px column and shifted every icon 12px right (svg x=27 instead of
   15). intrinsicContentWidth now honors an explicit CSS width before
   measuring content.

2. cache-ring-label (absolutely-positioned flex column, the "0% / 缓存命中"
   ring center) had height 0 — its two spans stacked on top of each other.
   distributeFreeSpace shrank every item because freeSpace = 0 − Σbase is
   always negative for an auto-sized container (mainSize 0). Shrink is now
   skipped when containerMainSize <= 0, so the label grows to its content
   (37.2px) and the percentage sits above the caption.

3. Right-panel text was flush against the panel edge: conv-stats-detail
   (flex:1) grew to 137px in a 129px slot because the flex free space never
   subtracted the inter-item gap (CSS-FLEXBOX §9.7: free space = container
   − Σbases − gaps). distributeFreeSpace now subtracts gap×(n−1); detail
   right edge moves 1280 → 1272, restoring the 8px right padding and the
   cs-val "总 Token" text margin.
