feat: border-collapse:collapse — shared borders, cell precedence, shrink-to-fit

Table border collapsing (CSS 2.1 §17.6) was entirely missing: wb-ui painted
each cell's borders independently (adjacent cells showed doubled lines) and
auto-width tables stretched to the available width instead of shrinking to
content.

New:
- style: BorderCollapse property (computedstyle_data.go, computedstyle.go,
  resolver.go) with collapse/separate parse.
- layout/tableformattingcontext.go:
  * collapse mode starts cells at the table border-box edge (cell borders
    replace the table's outer border).
  * applyCollapseBorders resolves conflicts per CSS: the first cell in DOM
    order (top/left) wins the shared line's color, the wider border wins the
    width, and the losing edge is zeroed so each line paints once. The
    table's own outer border is maxed against the outermost cell (cell
    painted later covers it).
  * explicit cell width + padding + border feeds the column (matches Edge:
    width:80 + 2px borders + 1px padding → 86px column).
- layout/blockformattingcontext.go: auto-width tables now shrink-to-fit
  (tablePreferredWidth = max-content column sum), never stretched to the
  container width (Edge: 172px not 284px).

Pixel cases added: single-row collapse table (0.4% diff — Edge's sub-pixel
outer border placement at the far right) and 2x2 multi-row (1.07%).

Verified: pixel suite 9/9, GEO suite 13/13, go test ./... green.
