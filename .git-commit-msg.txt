fix: dispatch DOM click on release + multi-line caret placement

Comprehensive interaction test (rendering/interaction_test.go) covering
clicks / checkbox toggling / single + multi-line caret placement exposed
two engine bugs that made the desktop IDE feel dead:

1. Clicks never reached JS listeners. host.go's handleClick was never
   called (dead code) and the release path only cleared active state, so
   Vue @click handlers (registered via addEventListener('click')) never
   ran — every button/icon/switch did nothing. handleClick is now invoked
   on mouse-button release and dispatches a bubbling DOM click to the
   hit-tested element, so addEventListener listeners fire (verified on the
   real companion frontend: clicking ws-create-btn now opens the
   workspace dialog).

2. Multi-line textarea caret landed wrong. calcTextControlOffset used a
   hardcoded Consolas 14 and ignored the Y axis entirely — clicking line
   2+ always returned an offset on line 1. The logic is extracted to
   rendering.CalcFormControlCaretOffset (pure function) which resolves
   the clicked line from Y, then the column from X with cumulative widths
   (the column loop was also missing the running-total accumulator, so it
   always returned end-of-line). The caret now uses the element's
   computed font/padding, matching the painted text.

New tests: TestClickDispatchFiresJSListener, TestCheckboxToggleOnClickClick,
TestCaretSingleLineInput, TestCaretTextareaMultiLine,
TestClickBubblesToAncestor. rendering/layout/app/bindings/dom/page/
webkit/html5 all green.
