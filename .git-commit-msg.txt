feat: background-image url() support + two paint bugs

Candidate: image backgrounds with background-size/position.

New rendering/backgroundimage.go — full url() background path:
- parseBackgroundURL (quotes, data URIs), decodeDataURI (base64),
  loadBackgroundImage (data: + file paths, cached), computeBackgroundDest
  (background-size: auto/cover/contain/length/% and background-position:
  keywords/%/px against the box−image delta), parseBackgroundSize/Position.
- painter.go paints url() backgrounds before the gradient path.
- style/resolver.go background shorthand recognizes url(...) layers.

Two real bugs found and fixed by the new path:
1. css/rule.go serializeToken had no TokenURL case → url() values
   serialized to "" → background-image silently lost. Now "url(...)".
2. platform/graphics/canvas.go DrawImage passed (x, y, x+w, y+h) to
   skia.RectXYWH — the destination rect was double-size, so images drew
   into a 2x box. Fixed to (x, y, w, h); affects <img> painting too.

Tests: unit tests for parsing (url/data-URI/size/position incl. px+%
+keywords), paint test asserts the centered image rect is red and the
corner/outside stays transparent. GEO 13/13, go test green.
