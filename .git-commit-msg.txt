feat: fix CJK tofu + word-break/overflow-wrap character breaking

Full-scan round:

1. CJK tofu fix (fontmgr.go):
   - selectDefaults previously preferred OS "Arial" as the default sans —
     Arial has no CJK glyphs, so text without an explicit font-family relied
     on Skia's unstable system fallback (part of the UI rendered tofu boxes
     while components with font-family picked YaHei fine).
   - Now: sans-serif/default prefers OS "Microsoft YaHei" (CJK coverage +
     intact system fallback chain), then raw msyh data, then Segoe UI, then
     Arial as LAST resort. serif prefers OS "SimSun" (Chinese serif) over
     kochi mincho.
   - resolveFamily maps additional CJK family names (PingFang SC, SimHei,
     SimSun, NSimSun, Hiragino, WenQuanYi, Noto Sans CJK) to YaHei so
     font-family lists like "PingFang SC, Microsoft YaHei" resolve correctly.
   - Verified via dev/fontprobe: default path ink 292→483 (YaHei glyphs
     instead of Arial fallback); all 10 resolution paths render CJK.

2. word-break / overflow-wrap (inlineformattingcontext.go + resolver.go +
   wordbreak_test.go):
   - Previously a single word wider than the whole line could not break —
     long URLs / CJK-free words overflowed the container.
   - New: when wordWidth > line availWidth and word-break:break-all (or
     overflow-wrap:break-word), the word is split per character with proper
     line wrapping (no space prefix, mirrors WebCore break-word handling).
   - Resolver now parses word-break and overflow-wrap (word-wrap alias).
   - Verified: 20-char word in 60px box splits across >=2 lines with
     break-all / break-word; without a rule it overflows on one line.
