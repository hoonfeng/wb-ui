fix: transparent borders must not paint

User report: elements with no visible border were drawing one — every
toolbar icon button (.tb-btn, .rp-btn) uses `border: 1px solid
transparent` and got a solid black outline.

Root cause: BorderColor(side) treated a zero-value color (transparent)
as "unset" and fell back to currentColor (black), so explicitly
transparent borders painted as black. CSS distinguishes the two:
`border: 1px solid transparent` stays invisible (occupies layout space
only), while a border with NO color keyword falls back to currentColor.

Fix:
- parseBorderShorthand now returns colorSet (whether a color keyword was
  present, including transparent).
- NonInheritedData gains Border{Top,Right,Bottom,Left}ColorSet; the
  border/border-side shorthands record it.
- BorderColor(side) falls back to currentColor ONLY when the color was
  not set; an explicit transparent stays A=0 so painters skip it.
- painter.go rounded-rect fast path additionally guards A>0.

Verified vs Edge on the real companion frontend: pixel diff
28823->27992 (-831), titlebar band 1246->946, toolbar band 1904->1608,
rp-header buttons 3813->3513. GEO 13/13, full go test green.

Test: TestTransparentBorderColor (transparent keeps A=0, unset falls
back to currentColor).
