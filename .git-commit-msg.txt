fix: SVG currentColor timing — icons were completely invisible

Regression introduced by the previous round: paintObjectForeground set
doc.currentColor AFTER buildSVGDocument returned, but the walk inside
build parses fill/stroke="currentColor" DURING the build — so every
currentColor stroke resolved to the zero-value color (A=0 transparent)
and ALL svg-icon paths were skipped (draw log: "path SKIPPED stroke:
stroke.A=0"). The desktop app showed NO SVG icons at all.

Fix: buildSVGDocument now takes the host element's CSS color as a
variadic parameter and seeds doc.currentColor BEFORE the walk runs.
paintObjectForeground passes box.Style().Color (default black when no
style context, per the SVG spec).

Verified with draw logs (WB_SVG_DEBUG=1): every icon now strokes with a
valid currentColor (#e6edf3 / #6e7681 / #ffffff / #79c0ff …) and the
activity-bar folder icon draws 219 ink px vs Edge's 218 (was 85 when
broken, body missing). Send-btn paper plane strokes white, obtn icons
colored per button. Activity-bar diff region 2093 -> 1560 px.

Also kept WB_SVG_DEBUG-gated draw logs in svgPath/svgPolygon/svgEllipse
paint as a diagnostic tool for future rounds.

Full go test green; GEO 13/13.
