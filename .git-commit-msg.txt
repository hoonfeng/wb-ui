feat: SVG <style> rules + transform + arc paths + multiline text

Candidates round:

1. SVG <style> sheet rules (svg.go + svg_style_test.go):
   - <style> content parsed via css.NewParser; fill/stroke/stroke-width
     declarations collected per rule (class or tag selector).
   - Precedence: inline attribute > style="" > stylesheet rule (SVG
     presentation-attribute semantics). matchSVGStyleRule matches ".cls" in
     the element's class or a bare tag name.
   - Verified: .redBox/.blueBox classes fill two rects; inline fill wins.

2. SVG transform attribute (svg.go + svg_style_test.go):
   - transform="translate(...)/scale(...)/rotate(...)" applied on the shape
     via canvas.Save + applyTransformOps + Restore (reuses the CSS transform
     pipeline); also composes with gradient fills and clip paths.
   - Verified: translate(30,20) shifts the rect; scale(2) doubles it.

3. SVG path arc commands A/a (svg.go + svg_style_test.go):
   - Elliptical arcs were parsed but never drawn. Added arcToPolyline: the
     SVG 1.1 F.6.5 endpoint→center conversion (radius correction, large-arc/
     sweep flags, angle sweep) sampled at 24 points with relative-command
     support.
   - Verified: two half-ellipse arcs stroke top/bottom of an ellipse.

4. SVG text multiline (svg.go + svg_style_test.go):
   - <text> with \n paints each line at baseline + i*lineHeight (1.2em);
     tspan content already flows through TextContent. text-anchor applies
     per line.

5. CSS mask — parse/storage only (mask_test.go):
   - mask-image flows through the resolver's generic SetProperty storage and
     painting with it set doesn't panic. Full image-as-alpha rasterization
     is deferred (no skia API for it; pixel loop ROI low).

Tests: style classes + inline precedence, transform translate/scale, arc
stroke, multiline text, mask no-crash. Full go test green.
