fix: keep drag selection End on release (don't recompute from release point)

User reported: after drag-selecting text, releasing the mouse changed the
selection. Root cause: the Release branch recomputed FocusedFormControlSel.End
from the release coordinates. When the mouse is released outside the control
(or after a fast drag where the last mousemove and the release point differ),
End jumped to a clamped position instead of staying at the last drag position.

Browsers keep the selection established by the final mousemove on mouseup.
The Release handler now only finalizes the drag state (selecting=false,
Active=false) and no longer rewrites End.

Verified with sim_drag_select: drag to End=22, release 200px below the
control → fixed keeps 22, old code recomputed to 45 (end of text).
