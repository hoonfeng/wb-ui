feat: SVG clip-path + <use> + multi-stop gradients + img object-fit/alt

Candidates round:

1. SVG clip-path application (svg.go + svg_test.go):
   - clip-path="url(#id)" now actually clips: svgFilledShape carries clipID;
     paint saves the canvas, builds a skia path from the clip shapes
     (rect/circle approximated) and clips the shape's paint.
   - Verified: rect fill=red clipped to left-half rect paints red left,
     transparent right.

2. SVG <use> elements (svg.go + svg_use_test.go):
   - Fixed href resolution: <use href="#id"> uses the #id fragment syntax,
     but parseURLReference only handled url(#id). The use branch now accepts
     both (reverting the earlier global #-prefix change that mis-parsed
     fill="#ffffff" as a reference and broke SVG strokes).
   - The referenced shape is pure geometry; its own fill is now resolved and
     wrapped so the use target is visible (paint context default fill is
     transparent). x/y offset via svgTranslatedShape verified at (30,40).

3. Multi-stop gradients (svg_gradient_test.go):
   - SVG linear gradients already rasterize pixel-columns via
     interpolateColor (CSS gradient code) so 3+ stops work; TestSVGMultiStopGradient
     verifies red → green → blue across the rect.

4. img object-fit (painter.go + objectfit_test.go):
   - cover/contain/none/fill implemented in PaintImage (10x20 image in
     60x30 box: contain letterboxes left/right, cover fills+crops, none
     draws natural size top-left).

5. Image fallback alt text (painter.go + objectfit_test.go):
   - PaintImage paints the alt attribute when the image can't be decoded
     (broken src / async http not yet arrived), using the element color.

Tests: clip left-half red/right-transparent, use rect at offset in blue,
3-stop gradient red/green/blue, object-fit contain/cover/none, alt fallback.
