fix: hit-test zero-area swallow + text-align center reference

Fixes the blue "创建 / 新建终端" buttons: clicks did nothing, the
labels were tiny and off-center.

1. Hit-test swallowed ALL clicks (ws-create-btn / term-create-btn /
   term-tab new-tab all resolved to the empty position:fixed
   .toast-container). A 0x0 box was accepted as the first candidate
   (best==nil, area 0), and since every later element's area > 0 could
   never beat 0, the empty container permanently won and blocked the
   whole viewport. Zero-area boxes are now skipped as hit candidates;
   buttons hit-test correctly.

2. text-align:center used containerWidth captured AFTER the auto-width
   expansion (+20px) as its centering reference, so centered text inside
   a flex-item span/button sat ~10px right of the box center ("创建" was
   off-center inside the blue button). containerWidth is now captured
   before the expansion; span "暂无工作区" X 159.9→149.9, button "创建"
   X 214.6→204.6 (exact padding-10 offset), both centered.

3. desktop_probe never initialized the FontManager, so CJK measured via
   a bare Arial fallback (创建=15.5px → 35.5px button) while painting
   used Skia's system fallback — inconsistent widths made the button
   small and text cramped. main.go now mirrors host.go: InitFontManager
   + LoadSystemFonts + MeasureTextFunc/FontMetricsFunc; the button grows
   to 44px matching Edge.
